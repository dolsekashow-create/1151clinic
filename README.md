# النظام المركزي لإدارة الفروع

منصة ويب مؤسسية لإدارة عمليات شركة متعددة الفروع: التنظيم، المستخدمون والصلاحيات، العملاء، الخدمات والحجوزات، المخازن، المشتريات، المالية والخزائن والورديات، الإشعارات، التقارير، وسجل التدقيق.

> **الحالة:** المرحلة 1 (الأساس) والمرحلة 2 (الأمان والهوية) **مكتملتان ومُختبَرتان**،
> بالإضافة إلى أساس قاعدة البيانات وسياسات الحماية لكل وحدات المراحل 3–6.
>
> ⚠️ الترحيلات **لم تُطبَّق بعد** على مشروع Supabase الحقيقي — راجع [DEPLOYMENT.md](docs/DEPLOYMENT.md) §6.

---

## المبدأ الحاكم للمشروع

المتطلبات التفصيلية للأقسام **لم تُعتمد بعد**. لذلك:

- نبني **البنية** الآن (قابلة للتوسع والتعديل).
- كل قاعدة عمل غير معتمدة مُسجّلة صراحةً في
  [`packages/core/src/pending/registry.ts`](packages/core/src/pending/registry.ts)
  و[`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md) §2.
- استدعاء أي قاعدة معلّقة يُرجع `BUSINESS_RULE_PENDING` (501) بدل تنفيذ منطق مُخترَع.
- **الافتراضات مفصولة عن المتطلبات المؤكدة** في مستند المتطلبات (§4 و §5) — لا خلط بينها.

## ما هو مبنيّ فعلًا

| الطبقة | الحالة |
|--------|--------|
| قاعدة البيانات | **42 جدولًا** + فهارس + قيود، في 7 ملفات ترحيل |
| الحماية | RLS على كل جدول، مُولَّدة من قالب واحد مُراجَع |
| اختبارات RLS | **38 اختبارًا** على محرّك PostgreSQL حقيقي — كلها تمر |
| اختبارات الوحدة | 17 اختبارًا لطبقة التخويل والكتالوج |
| المصادقة | دخول، خروج، استعادة كلمة مرور، حماية المسارات، تحديث الجلسة |
| RBAC | 54 صلاحية · 8 أدوار أولية · نطاق منشأة/فرع |
| الخادم | غلاف موحّد يفرض: مصادقة → صلاحية → تحقق → تنفيذ → تدقيق |
| الواجهة | هيكل لوحة التحكم كاملًا + وحدة العملاء مُنفَّذة بالكامل |
| التجريدات | الإشعارات (SMS/Email/Push/WhatsApp)، التقارير والتصدير، الملفات، التكامل |

## التقنيات

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| الواجهة | Next.js 15 (App Router) + React 19 + TypeScript | عرض من الخادم، أنواع من طرف لطرف |
| التنسيق | Tailwind CSS v4 + نظام تصميم داخلي | توحيد الواجهة ودعم RTL بخصائص منطقية |
| قاعدة البيانات | Supabase / PostgreSQL | علاقات حقيقية + RLS للعزل |
| المصادقة | Supabase Auth | لا نتعامل مع كلمات المرور إطلاقًا |
| المستودع | pnpm workspaces + Turborepo | حدود فيزيائية بين الطبقات |
| الاختبار | Vitest + node:test + PostgreSQL مضمّن | اختبار RLS على المحرّك نفسه، بلا Docker |

قرار عدم فصل الـ Backend في خدمة مستقلة (ومتى يُعاد النظر فيه) موثّق في
[`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) §2.

## البنية

```
apps/web        تطبيق Next.js — العرض + الـ API
packages/core   المجال وحالات الاستخدام (TypeScript خالص، بلا Next/React/Supabase)
packages/ui     نظام التصميم
packages/types  الأنواع المشتركة + أنواع قاعدة البيانات المُولّدة
packages/config إعدادات TypeScript المشتركة
scripts/        مولّدات (seed الصلاحيات، أنواع قاعدة البيانات)
supabase/       الترحيلات والبذور واختبارات RLS
docs/           التوثيق المعماري والأمني والمتطلبات
```

**قاعدة معمارية مُلزِمة:** `packages/core` ممنوع أن يستورد من `next` أو `react` أو `@supabase/*`.
هذا ما يجعل استخراج خدمة Backend مستقلة مستقبلًا ممكنًا بلا إعادة كتابة.

## التشغيل

```bash
pnpm install
```

⚠️ **ملف البيئة في `apps/web/` لا في جذر المستودع** — Next.js يقرأ البيئة من جذر التطبيق:

```bash
cp apps/web/.env.example apps/web/.env.local
```

```bash
pnpm dev
```

التطبيق على http://localhost:3000 · فحص الاتصال: `GET /api/health`

### الأوامر

| الأمر | الوظيفة |
|-------|---------|
| `pnpm dev` | تشغيل بيئة التطوير |
| `pnpm build` | بناء كل الحزم والتطبيق |
| `pnpm typecheck` | فحص الأنواع |
| `pnpm lint` | فحص جودة الكود |
| `pnpm test` | اختبارات الوحدة |
| `pnpm test:rls` | **اختبارات RLS على PostgreSQL حقيقي** (بلا Docker) |
| `pnpm test:all` | الاثنان معًا |
| `pnpm db:seed:generate` | توليد seed الصلاحيات من كتالوج الكود |
| `pnpm db:types:generate` | توليد أنواع TypeScript من ملفات الترحيل |
| `pnpm db:push` | تطبيق الترحيلات على مشروع Supabase المرتبط |

## الأمان — ملخص

- العزل الحقيقي في **PostgreSQL RLS**، لا في الواجهة. مُثبَت باختبارات على المحرّك.
- كل نقطة دخول: مصادقة → صلاحية → تحقق مدخلات → منطق → تدقيق.
- المفتاح السرّي محصور في ملف يستورد `server-only` ⇒ استخدامه من العميل يفشل عند البناء.
- `organization_id` لا يُقبل من العميل — يُشتق من الجلسة.
- الدفاتر المالية والمخزنية وسجل التدقيق **غير قابلة للتعديل أو الحذف**.
- لا أسرار في المستودع؛ CI يفشل عند رفع ملف بيئة.

التفاصيل وما لم يُختبر بعد: [`docs/SECURITY.md`](docs/SECURITY.md) §6.
